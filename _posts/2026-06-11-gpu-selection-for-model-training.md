做深度学习训练，选什么 GPU 是一个绕不开的问题。显存大小、带宽、算力、互联方式，每个参数都会直接影响训练效率和模型规模的上限。这篇文章梳理一下主流 GPU 的核心参数和选型思路。

## 主流训练 GPU 参数速览

先看一张对比表（数据基于官方标称值）：

| GPU | 显存 | 显存带宽 | FP16 TFLOPS | NVLink | 典型单卡功耗 |
|-----|------|---------|-------------|--------|------------|
| H200 | 141 GB HBM3e | 4.8 TB/s | 989 | 900 GB/s | 700W |
| H100 SXM | 80 GB HBM3 | 3.35 TB/s | 989 | 900 GB/s | 700W |
| H100 PCIe | 80 GB HBM2e | 2.0 TB/s | 756 | 无 | 350W |
| A100 SXM | 80 GB HBM2e | 2.0 TB/s | 312 | 600 GB/s | 400W |
| A100 PCIe | 80 GB HBM2e | 1.9 TB/s | 312 | 无 | 300W |
| L40S | 48 GB GDDR6 | 864 GB/s | 362 | 无 | 350W |
| RTX 6000 Ada | 48 GB GDDR6 | 960 GB/s | 364 | 无 | 300W |
| RTX 4090 | 24 GB GDDR6X | 1.0 TB/s | 330 | 无 | 450W |

## 显存：第一约束条件

选卡时**先看显存，再看算力**。显存不够，模型根本跑不起来；算力不够，顶多是慢一点。

训练显存占用主要由以下部分组成：

1. **模型参数**（以 FP16/BF16 混合精度训练为例）：参数量 × 2 bytes。一个 7B 模型占 ~14 GB。
2. **优化器状态**（AdamW）：参数量 × 8 bytes（fp32 master weight + momentum + variance）。7B 模型额外要 ~56 GB。
3. **梯度**：参数量 × 2 bytes。7B 模型 ~14 GB。
4. **激活值**（activation）：取决于 batch size、序列长度和模型架构。这是变量最大的一块。

以上加起来，**全量训练一个 7B 模型大约需要 100 GB+ 显存**。所以：

- **<= 7B 全量训练**：至少要 A100 80GB 单卡 + gradient checkpointing + 梯度累积，或者直接上多卡。
- **<= 1B 模型**：L40S / RTX 6000 Ada 的 48 GB 可以承担。
- **LoRA / QLoRA 微调**：对显存要求大幅降低。7B 模型用 QLoRA，RTX 4090（24 GB）就可以跑。

### 为什么 RTX 4090 看起来算力不错却不适合做大模型训练？

24 GB 显存是硬伤。算力有 330 TFLOPS FP16，但一个 7B 模型模型参数就吃掉 14 GB，加上优化器状态就爆了。4090 适合做推理或小模型的微调，不适合做大模型的全量训练。

## 显存带宽：影响训练吞吐的关键

显存带宽直接决定数据在计算单元和显存之间的搬运速度。大模型训练是 **memory-bound** 的，尤其是 decoder-only 架构的自回归生成阶段。

对比一下：

- H200：4.8 TB/s —— 几乎是 H100 PCIe 的 2.4 倍
- H100 SXM：3.35 TB/s
- A100 80GB：2.0 TB/s
- L40S：864 GB/s —— 只有 A100 的 40%

在做大批量数据的预训练时，带宽瓶颈会非常明显。如果你在 A100 和 L40S 之间犹豫，而场景是大规模预训练，**无脑选 A100**。带宽差距太大，L40S 补不回来。

## 算力：TFLOPS 不是唯一指标

FP16/BF16 TFLOPS 是衡量训练速度的核心指标，但要注意：

1. **实际利用率**：标称算力 ≠ 实际算力。受限于显存带宽和通信开销，实际利用率通常在 40%–60%。
2. **稀疏算力**：NVIDIA 官方标注的往往是包含稀疏性加速的数据（如 H100 的 1979 TFLOPS），上表中的数值已折算为稠密算力。
3. **BF16 vs FP16**：二者算力基本一致，但 BF16 数值范围更大，训练大模型时更稳定。

## NVLink 与多卡扩展

单卡搞不定的时候就要上多卡。多卡训练的核心瓶颈是 **卡间通信**。

- **H100 / A100 SXM**：NVLink + NVSwitch，多卡间通信带宽高，扩展效率好。
- **PCIe 版本**：没有 NVLink，卡间通信走 PCIe 或通过 InfiniBand/RoCE 网络。PCIe Gen5 ×16 双向带宽不过 128 GB/s，和 NVLink 的 900 GB/s 差了近一个数量级。
- **RTX 4090**：完全不支持 NVLink，多卡训练通信成本很高，不适合做需要多卡并行的大模型训练。

**经验法则**：需要 4 卡以上做数据并行 / 模型并行训练时，选 SXM 版本。单卡或双卡 PCIe 可以接受。

## 选型决策树

```
你的场景是什么？
│
├── 预训练 >= 7B 模型
│   ├── 预算充足 → H100/H200 SXM 多节点集群
│   └── 预算有限 → A100 80GB SXM 多卡（二手市场性价比高）
│
├── 全量微调 >= 7B 模型
│   ├── 有 NVLink 需求 → A100 80GB SXM 单卡/双卡
│   └── 显存够就行 → A100 80GB PCIe 单卡 + gradient checkpointing
│
├── LoRA / QLoRA 微调（任意尺寸）
│   ├── 72B 模型 → A100 80GB 或 2×L40S
│   ├── 7B 模型 → RTX 4090 / L40S / A100（看预算）
│   └── <= 1B 模型 → RTX 4090 绰绰有余
│
└── 推理
    ├── 大模型服务 → H100 / A100（带宽优势明显）
    ├── 小模型/local → RTX 4090
    └── 批量推理 → L40S 性价比不错
```

## 一些实际建议

1. **不要迷信最新最贵**：H100 比 A100 贵很多，但很多场景下 A100 80GB 完全够用。对于 academic lab 或个人开发者，A100 80GB 依然是甜点卡。
2. **显存是第一优先级**：宁愿要 80 GB HBM2e 的 A100，也不要 24 GB GDDR6X 的 4090 来做大模型训练。
3. **云 vs 自建**：偶尔跑实验就租云 GPU（Lambda Labs、Vast.ai、AutoDL 等），长期高频使用才考虑自建。一张 H100 SXM 的采购成本和云上租用的盈亏平衡点大约在 6–8 个月持续使用。
4. **关注二手市场**：A100 是 2020 年发布的产品，二手市场上存量不小，价格比新卡友好很多。对个人开发者或小团队来说，二手 A100 是目前做 7B 模型全量训练最具性价比的选择。
5. **显卡代际差别不是线性的**：H100 相比 A100，在同精度下算力提升了约 3 倍，但价格可能高 3–5 倍。算力/价格比并不一定是越新越好。

## 总结

| 场景 | 推荐配置 |
|------|---------|
| 个人学习 / 小模型微调 | RTX 4090 24 GB |
| 7B 模型 LoRA 微调 | RTX 4090 / L40S |
| 7B 全量训练 / 大模型微调 | A100 80GB |
| 70B+ 全量训练 | 多卡 H100 / H200 SXM |
| 大规模预训练 | H100 / H200 集群 |

选择 GPU 不是一个 "哪个最好" 的问题，而是 "哪个最适合你的模型规模、预算和使用频率" 的问题。希望这篇文章能帮你理清思路。
